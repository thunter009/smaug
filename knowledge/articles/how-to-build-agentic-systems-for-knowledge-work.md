Heinrich argues that agents working on a project or field over time need three things: knowledge and work that persist, a system fitted to how the person works, and a reusable foundation of domain knowledge and practices. He calls the discipline "knowledge work engineering" and presents Ars Umbris, a local-first framework for building it.

Key Takeaways:

- Knowledge systems combine domain objects and relationships, evidence, working methods (instructions, skills, tools, checks), ongoing work, and interfaces.
- Typed markdown lets a claim, decision, or commitment link to its evidence. The engine reports missing fields and broken or wrong-type references.
- Knowledge bases can be packaged and depended on across repos, like code packages, with wikilinks that cross repo boundaries.
- Agent repos bundle knowledge with skills, MCP tools, and interfaces such as citation graphs and review panels.
- Work should start from a real task. Structure grows as the work proceeds, and it should be revised as the author learns.
- Once a method proves useful, its types, skills, and interfaces can be packaged so others can apply it to their own material.
